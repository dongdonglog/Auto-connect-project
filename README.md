# Material Map

Material Map 是一款本地优先的桌面材料工作台。它将文件、笔记和链接收集到加密可选的本地工作区，再以可编辑的主题画板梳理它们的时间、上下文和关系。

项目使用 Electron、React 和 React Flow 构建。画板交互借鉴 [React Flow](https://github.com/xyflow/xyflow) 的受控节点/边模型、[Excalidraw](https://github.com/excalidraw/excalidraw) 的画布工具与上下文操作，以及 [tldraw](https://github.com/tldraw/tldraw) 的对象优先编辑方式；不会嵌入第二套白板文件格式。

> 当前处于积极开发阶段。请将其视为本地工作流工具，而不是唯一的数据备份或生产级协作服务。

## 功能

### 本地工作区

- 创建、打开、导入和导出 `.material-workspace` 工作区。
- 最近工作区记录最多保留 6 项，可直接打开或移除记录。
- 工作区数据和导入副本存放在本机；可选工作区加密。
- API Key 使用 Electron `safeStorage` 保存，不写入工作区包。

### 材料工作台

- 导入多个文件、拖入窗口、创建笔记和链接。
- 支持 Markdown、TXT、CSV、JSON、HTML、PDF、DOCX 等材料的提取和预览。
- Markdown 使用 CommonMark/GFM 渲染；HTML 经清洗；JSON 和 CSV 有专用视图。
- 导入队列显示排队、解析、完成、失败、重复和超过 10 MB 的暂停状态；失败材料可以重试。
- 同名文件按材料 ID 独立跟踪；重复内容可跳过或保留副本。
- 工作台每页最多显示 15 项，支持搜索、主题筛选、按主题排序，以及 Cmd/Ctrl、Shift、Esc 多选。
- 多选材料可创建新主题；删除所选只删除工作区材料记录，不删除原始源文件。

### 主题画板

- 基于 React Flow 的无限画布、缩放、平移、小地图、适配视图和右键菜单。
- 从画布新建卡片、导入文件、粘贴纯文本，或通过可搜索多选器从工作台加入材料。
- 拖动位置按“主题 + 材料”保存；自动排版使用 Dagre，默认不会覆盖手工位置。
- 卡片有稳定编号：默认按材料时间、导入时间、材料 ID 排序；可在画板属性中设为手动顺序，或恢复时间顺序。
- 卡片的颜色、标签、画板备注和顺序只作用于当前主题，不修改原文件或其他主题。
- 关系支持多分支，禁止自连接和同方向正式重复关系，允许反向关系。
- 在线中间选择和编辑关系名称、颜色、线型、两端箭头与动画；支持连续连线、删除、AI 建议显示/隐藏和归档。
- 主题可归档、恢复或永久删除主题记录。归档不会删除原材料或文件；恢复发现缺失材料时会创建“补齐文档”。

### AI 辅助

- 命名 AI 连接配置：填写名称、协议、地址和 API Key 后，应用尝试发现模型并选择可用推荐模型。
- AI 辅助连接先运行内置 `topic-connection` skill，以树/森林约束生成可审阅的建议关系。
- 内置连接缺少证据或失败时，用户可使用“对话 AI”请求当前主题内的操作建议。
- 对话 AI 只返回受限、逐项可应用的建议；不直接删除材料、编辑文件正文、修改其他主题或变更 AI 配置。
- AI 建议可以接受为正式关系，或归档而不删除数据。

## 快速开始

要求：Node.js 22+、npm。当前开发验证环境为 macOS；Windows 保留 NSIS 与 portable 的打包配置。

```bash
npm ci
npm run dev
```

首次启动后，创建工作区，再导入材料或写入笔记。选中工作台材料后可创建主题；在主题画板中从节点端口拉线建立关系。

## 常用流程

1. 创建或打开一个本地工作区。
2. 将文件拖入工作台，或一次选择多个文件导入。
3. 在工作台使用 Cmd/Ctrl 或 Shift 选择材料，选择“从所选创建主题”。
4. 打开主题画板，右键空白处新建卡片、导入或从工作台加入更多材料。
5. 从卡片端口拉出关系线，在关系中点修改名称和样式。
6. 需要整理时点击自动排版；需要 AI 时展开“AI 建议”，先审阅再接受或归档。
7. 完成后导出工作区；主题可先归档，而不会影响源材料。

## 架构

```text
src/main/
  workspace-service.ts  工作区、SQLite、迁移、导入、主题与关系事务
  ai-service.ts         模型调用与受限 AI 建议
  ai-skills/            主题连接与主题操作规范（每份少于 100 行）
src/preload/            类型化 Electron IPC 边界
src/renderer/src/
  features/topics/      主题页、画布、节点、边、工具栏、AI 建议
  lib/                  IPC 封装、Dagre 布局、标签放置纯函数
  App.tsx               应用壳与仍在迁移的工作台/设置界面
```

画板节点和边由 React Flow 受控状态管理。Dagre 只在用户明确点击“自动排版”时计算位置；位置、卡片属性和关系样式持久化在主题内，不改变材料正文。

## 开发与验证

```bash
# 类型检查
npx tsc --noEmit

# 单元测试
npm test

# Electron/Vite 生产构建
npm run build

# Windows NSIS 和 portable 包
npm run package
```

提交涉及工作区、导入、AI 或画板的改动前，请至少运行前三项。打包产物、工作区数据库、导出包和 API Key 均不应提交。

## 数据与隐私

- 材料、SQLite 数据库和索引默认位于本地工作区。
- 外部模型仅在用户主动发起分析或对话，并已同意云端使用时接收所需文本。
- 本项目不提供云端同步、多人协作或托管后端。
- 请自行保留工作区导出包作为备份。

## 已知限制与待完成项

以下项目尚未完成，或尚未在目标环境完成足够验收：

- 前端架构迁移尚未结束：`App.tsx` 仍保留旧工作台和旧画板代码，需彻底移除并把工作台、设置、弹窗继续拆到 feature 层；IPC 调用也尚未全部集中到 `lib/ipc.ts`。
- 关系标签目前采用几何偏移和基础标签占位，尚不是完整的节点/标签/标签三方碰撞避让系统；复杂密集图仍可能需要手动调整和进一步的布局算法。
- 连线端口方向目前仍以默认左右端口为主，尚未为每条关系持久化智能端口选择；复杂交叉关系的避障路由需要继续完善。
- AI 连接结果目前由分析服务直接写入 AI 建议层，而对话 AI 是逐项审阅建议；两条路径还需要统一成完全一致的“提案后应用”模型。
- 已归档的 AI 建议尚无独立的恢复列表；当前可保留数据但没有面向用户的浏览入口。
- 同一源路径的高并发导入状态同步、Office/PDF 大文件解析和失败恢复需要更多压力测试。
- macOS 与 Windows 的 Cmd/Ctrl 粘贴链路已做代码修复，但搜索、编辑器、设置和画布的实机回归尚未覆盖所有 Electron 版本。
- Windows 真机上的 NSIS / portable 安装、签名和升级验证尚未完成；macOS/Linux 安装包不在当前交付范围。
- 真实模型服务的模型发现和协议兼容性取决于服务商 API，尚未覆盖所有 OpenAI 兼容中转服务。
- 没有完整的 Electron 端到端测试套件、自动更新、崩溃上报或云端协作能力。
