# Material Map

一个 Windows 优先的本地材料工作区原型。它把文件、笔记和链接放进一个本地工作区，并尝试用主题、时间轴和工作线整理材料之间的关系。

> 状态：早期原型，尚不适合作为生产数据的唯一存储位置。

## 当前可用

- 创建、打开、导出本地工作区；工作区数据和导入副本保存在本机。
- 导入常见文件，创建笔记、Markdown、TXT、CSV、JSON、HTML 文档和链接。
- 创建主题、工作线、材料关系；二维图按时间和工作线展示材料。
- 文本材料可在应用内编辑并保存；编辑导入文本时创建工作区内的新版本。
- 支持本地 Ollama、OpenAI 兼容接口、OpenAI Responses、Claude 和 Gemini 的基础调用路径。
- AI 设置采用一份当前配置：保存后，问答和主题分析都使用同一个服务商、地址、模型与本机加密保存的 Key。

## 当前限制

- 二维图的手写连线交互仍不稳定，缺少成熟图编辑器应有的连线校验、边编辑、撤销和键盘操作。
- 最近工作区的底层记录与界面展示不一致；目标是可切换最近 10 个项目。
- 真实模型服务的端到端验证仍需完善。模型错误会显示请求路径、状态和响应摘要，但不同中转站的兼容性尚未全部验证。
- 拖放导入、导入进度、批量重复文件处理、外部源文件变更提示尚未完成。
- Markdown、CSV、JSON、HTML 预览是基础实现，不是完整编辑器或浏览器渲染引擎。
- PDF、Office、图片 OCR 的预览和解析失败恢复没有经过全面验收。
- 没有 Electron 端到端测试、自动更新、签名发布或跨平台打包支持。

## 路线图

### 下一阶段

- 使用成熟图编辑器方案重做二维图交互：可靠连接、拖拽、选中、删除、编辑关系和撤销。
- 将工作区切换器扩展为最近 10 个项目，并显示路径和最近打开时间。
- 完成当前 AI 配置的真实连接、聊天、主题分析验收，并补齐服务商错误诊断。
- 补齐拖放导入、文本编辑器体验和导入版本管理。

### 后续阶段

- 完整的文件预览、解析状态和失败重试体验。
- 语义搜索、引用式问答和本地模型体验优化。
- 加密工作区、迁移包和恢复流程的端到端验证。
- 安装包、签名、版本管理以及 macOS/Linux 打包评估。

## 本地开发

要求：Node.js 22+、Windows。

```bash
npm install
npm run dev
```

检查与构建：

```bash
npx tsc --noEmit
npm test
npm run build
```

Windows 打包：

```bash
npm run package
```

打包产物、构建输出、临时文件和本地工作区数据均不应提交到仓库。

## 数据与隐私

- 工作区材料、SQLite 数据库和索引默认保留在本机。
- 选择外部模型时，只有用户主动触发分析或问答且确认云端同意后，相关文本才会发送到该服务。
- API Key 使用 Windows 数据保护机制保存，不写入工作区或导出包。
- 不要把 API Key、工作区数据库或导出包提交到 Git。

## 贡献

这是一个处于快速迭代期的原型。提交改动前请至少运行类型检查和测试；涉及关系图、工作区数据或模型请求时，请补充相应的测试用例。
