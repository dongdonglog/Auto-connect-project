# Material Map v1.5 TDD：Proposal 驱动的视觉知识地图

状态：已确认，实施基线。本文在现有 Electron/SQLite 架构上增量扩展。

## 1. 架构边界

```text
React renderer
  -> typed preload IPC
Electron main
  |- WorkspaceService: SQLite、topic command、迁移、备份
  |- CanvasAiService: 上下文、provider 调用、plan -> proposal
  |- CanvasPlanValidator: 纯函数 JSON 校验和归一化
  |- AppStore: provider profile、密钥和云端授权
  `- SQLite + FTS5 + optional sqlite-vec
```

renderer 不直接访问 SQLite、文件系统、密钥或模型 endpoint。所有正式写入继续经过 main process。

## 2. Canvas AI 协议

```ts
export interface CanvasAiRequest {
  topicId: string
  selectedMaterialIds: string[]
  instruction: string
  baseRevision: number
  allowCloud: boolean
  maxActions?: number
  maxContextChars?: number
}

export interface CanvasAction {
  id: string
  kind: 'create_relation' | 'create_workstream' | 'rename_relation' | 'set_sequence' | 'set_card_style' | 'layout'
  reason: string
  evidence: string
  materialId?: string | null
  relationId?: string | null
  payload: Record<string, unknown>
}

export interface CanvasAiPlan {
  runId: string
  topicId: string
  baseRevision: number
  summary: string
  actions: CanvasAction[]
  warnings: string[]
  model: { provider: string; model: string }
}
```

`CanvasAiService` 只返回校验后的 plan，并通过 `WorkspaceService.createTopicProposals` 持久化 proposal。旧的主题分析接口保留兼容，但 v1.5 画板入口统一走 proposal。

## 3. 数据迁移

新增 `topic_proposal_runs`：

- `id`, `topic_id`, `base_revision`, `instruction`
- `provider`, `model`, `summary`, `status`
- `created_at`, `updated_at`

为 `topic_proposals` 增加可空 `run_id`、`base_revision` 和 `source` 字段。旧记录默认 `source='legacy'`，`base_revision` 使用创建时主题 revision 或 `NULL`。

为 `topics` 增加 `view_mode` 和 `confirmed_only`，默认分别为 `map` 和 `0`。所有迁移通过 `PRAGMA table_info` 检测，不能删除旧表或旧字段。

## 4. 提案应用

接受 proposal 前：

1. 校验 proposal 属于目标 topic 且状态为 `pending`。
2. 若 `base_revision` 非空且与当前 topic revision 不一致，返回 `proposal-stale`，不执行 command。
3. 将 action 转换为现有 `TopicEditorCommand`。
4. 在一个 SQLite transaction 中应用所有 action。
5. 成功后更新 proposal/run 状态并进入现有历史；失败则回滚全部变更。

新增批量 IPC：`topics:acceptProposals(topicId, proposalIds)`，返回应用后的 proposal 列表和新 revision。单项接受复用同一事务实现。

## 5. 画板实现

- `TopicCanvas` 继续使用 `@xyflow/react`，不引入第二套画布引擎。
- 新增 `CanvasAiPanel` 负责指令、模型状态、上下文范围和 plan 请求。
- 新增 `canvas-diff` 纯函数，把 proposal 转成 overlay 节点/边/分组。
- 新增 `topic-view-presets` 纯函数，隔离 map/flow 的布局和筛选规则。
- workstream 使用现有 `workstreams` 表和 `workstreamId` 字段，不新建分组模型。
- 节点和边使用稳定 memo 数据；布局只在明确切换 flow 或点击自动布局时执行。

## 6. 错误处理与安全

- provider 未配置、未授权、超时、限流、HTTP 错误、非法 JSON 和未知材料 ID 均返回结构化错误。
- 云端发送前显示材料范围和授权状态；未授权请求在 main process 拒绝。
- 模型上下文只包含选区、必要邻接关系和证据摘要，限制总字符数。
- AI 不得执行文件写入、材料删除、静默关系提交或绕过 proposal。

## 7. 测试与质量

新增纯函数单测、WorkspaceService 集成测试、AI provider 失败测试和 Electron E2E。性能基准固定生成 100/300/500 节点与关系，并记录加载、fitView、拖拽和布局时间。

每次主进程、IPC、schema 或画板核心变更执行：

```bash

npm run test:ci
npm run build
npm run test:e2e
```
