# Material Map 文档总览

状态：`0.1 本地知识探索器` 已发布，`v1.5 AI 原生视觉知识地图` 进入实施。本文是产品与工程文档的入口；具体实现契约以同目录的设计文档和代码为准。

## 产品定位

Material Map 是一个本地运行的材料关系探索工具：打开一份文件，即时看到有证据支持的关联材料，并能继续阅读、跳转、固定或隐藏关系。

它不是云端文档系统，也不是以聊天为中心的 RAG 产品，更不依赖 AI 对整个工作区进行默认建图。核心价值是让用户理解自己的文件为什么相关。

## 0.1 决策

- **工作台是首屏**：导入、浏览和组织材料从这里开始。
- **探索是关系发现入口**：材料卡点击进入三栏 Explorer；本地查询默认最多展示 5 条可解释关系。
- **主题画板是编辑器**：用户在画板中组织材料、手动连线和调整关系属性；它不承担默认关系发现。
- **AI 是按需增强**：用户选择单条关系后才可请求 AI 解释或核验。没有 AI 配置、模型失败或离线时，本地探索仍然可用。
- **问答是独立实验页**：它使用本地检索与引用回答，不参与实体提取、关系排序或自动建图，也不混入工作台。

## 本地关系管线

```text
导入 / 文件监听 / 重新索引
  -> 本地解析标题、章节、正文、链接、代码引用
  -> 提取受控技术实体与显式文件引用
  -> 写入 SQLite 的实体、命中、证据和材料关系
  -> Explorer 按“显式引用 > 实体重叠 > 弱结构信号”查询
  -> 用户固定 / 隐藏，或在画板中编辑正式关系
```

每条自动关系都应能返回可定位的证据。高频通用词不能单独产生关系，避免文件较多时出现全连接噪声。

## 技术基线

```text
React renderer
  -> typed preload IPC
Electron main
  |- WorkspaceService：导入、解析、FTS、实体与关系
  |- AiService：带引用问答、单条关系解释
  |- AppStore：模型配置与本机密钥管理
  `- SQLite + FTS5 + optional sqlite-vec
```

- SQLite 是唯一权威数据源，包含材料、索引、关系、证据和主题画板数据。
- 工作区通过现有 `.material-workspace` 导出与恢复；不新增独立 `graph.json`。
- 现有手动关系与旧 AI 关系保留；旧标签/候选表只用于兼容历史工作区，不再作为新关系发现或 Explorer 的数据来源。
- 材料、索引和关系默认留在本机。外部模型必须经过用户配置与隐私确认。

## 当前范围

0.1 仅自动识别技术实体、项目/模块名及可解析的文件引用。人名、组织名、开放域概念抽取、跨工作区图谱、云同步和自动修改文件均不在范围内。

关系状态为：`visible`（自动可见）、`hidden`（用户隐藏）、`fixed`（用户固定）。固定关系可进入主题画板；自动但未固定的关系不强制绘制到画布。

## 0.1 验收基准

- 在 20 至 50 份材料的工作区中，打开材料后本地关联查询应在 1 秒内返回，默认最多 5 条。
- 显式文件引用优先于实体重叠；关系能展开证据并跳转到来源位置。
- 隐藏、固定、重新索引、重启以及工作区导出/恢复后，用户关系状态保持一致。
- 任意两张画板卡片的四边端口都可创建并持久化正式关系。
- AI 只读取用户选择的一条关系及紧凑证据；失败时不影响本地结果。
