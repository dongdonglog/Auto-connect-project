# Material Map 0.1 执行计划（待审批）

状态：`待产品审批，未开始实施`。依据 [PRD](./01_PRD.md)、[MVP 开发计划](./08_MVP开发计划.md) 与 [GitHub Issue 拆解](./09_GitHub_Issue拆解.md) 制定。本计划将 0.1 收敛为“本地、可解释、可控的材料关系探索闭环”。

## 1. 发布目标

用户无需配置 AI，就能完成：

```text
导入材料 -> 从工作台打开材料 -> Explorer 查看证据关系
-> 跳转关联材料 -> 固定到主题 -> 画板编辑正式关系
-> 刷新/重启/导出恢复后保持
```

发布时不交付批量 AI 建图、全局自动画布、Agent、云同步或协作。

## 2. 当前基线

已具备：SQLite 关系/证据表、Explorer 三栏与最多 5 条关系、显式引用和技术实体的关系雏形、隐藏/固定、四边端口和端口持久化、单条 AI 解释、工作区导入导出。

尚未满足发布：显式引用的可靠定位、真正增量重算、固定关系的主题归属、Explorer 状态与证据定位、旧批量候选路径清理、完整 E2E/性能基准/Windows 实机验证。

## 3. Agent 角色与边界

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| `Graph & Data` | 解析、实体、关系、SQLite 迁移、增量重算、工作区兼容 | Renderer 展示与样式 |
| `Explorer & Canvas` | Explorer、证据阅读、主题选择、画板交互与可访问性 | 直接访问 SQLite、定义解析规则 |
| `IPC & AI` | 类型安全 IPC、单条 AI 解释、隐私同意、错误处理 | 默认关系发现、批量 AI 建图 |
| `QA & Release` | fixture、单元/E2E、性能基准、打包与 Windows 验收 | 为了测试改写产品范围 |
| `Integration Owner` | 依赖协调、代码审查、迁移/兼容门槛、发布判定 | 跳过任一质量门禁 |

任何 agent 只能修改所属边界；跨边界需求通过已确认的 IPC 契约交接。每个工作包合并前必须有对应测试和回归说明。

## 4. 执行阶段

### 阶段 A：关系正确性（P0）

**负责人：Graph & Data；QA 并行准备 fixture。**

1. `G-01` 建立关系引擎 fixture：Markdown link、相对路径、TS/JS/Python/Go import、中文文件名、外链、泛词与无证据材料。
2. `G-02` 解析显式引用的原文、来源类型和 offset，按规范化相对路径解析到工作区材料；关系方向固定为“引用方 -> 被引用方”。
3. `G-03` 将重算改为“变更材料 + 直接候选”，事务化更新证据与关系；移除打开工作区时的全量关系重建。
4. `G-04` 以无向材料对保留 `hidden`/`fixed`，并处理删除材料、失联材料和孤儿 evidence。
5. `G-05` 补齐 schema 约束、索引与旧工作区迁移测试。

**验收**：外链和通用词不建边；显式引用优先；单文件编辑不触发全量重建；状态经过重启和工作区恢复保持；旧工作区可打开。

### 阶段 B：Explorer 到主题的闭环（P0）

**负责人：Explorer & Canvas；依赖阶段 A 的关系和证据契约。**

1. `E-01` 补齐 Explorer loading、无关系、解析失败、材料失联和请求失败状态。
2. `E-02` 关系卡展示关系类型、分数与证据；文本材料按 offset 高亮/定位，PDF 按页码或证据摘录降级定位，绝不跳到空白区域。
3. `E-03` 实现“固定到主题”的选择/创建流程。主进程提供原子操作：固定关系、保证两份材料属于主题、创建或复用正式关系。
4. `E-04` 提供隐藏关系恢复入口，避免用户只能永久隐藏。
5. `E-05` 固定关系进入画板；画板只显示手动关系与已固定关系。

**验收**：从工作台打开材料后最多 5 条关系在 1 秒内可见；证据可读且可跳转；固定一次后主题内有唯一可编辑正式边；隐藏可恢复。

### 阶段 C：画板与旧路径收敛（P0）

**负责人：Explorer & Canvas；Graph & Data 审核兼容性。**

1. `C-01` 验证并完善任意四边端口组合、方向、箭头、路径、颜色和属性持久化。
2. `C-02` 画板布局只使用正式关系：无关系网格，有 DAG 按真实层级；不生成编号、时间或“下一步”边。
3. `C-03` 从新用户 UI、默认调用链和 IPC 主路径移除旧候选虚线、批量 AI 精炼和主题自动建图入口。
4. `C-04` 保留 `material_tags`、`topic_relation_candidates` 和历史正式 AI 关系的读取兼容；不再作为新关系发现或渲染来源。

**验收**：新主题没有候选虚线和批量 AI 入口；旧工作区打开/导出/恢复不失败；任意端口关系刷新后不变。

### 阶段 D：IPC、AI 与实验问答（P1，不阻塞本地闭环开发）

**负责人：IPC & AI；Explorer & Canvas 消费。**

1. `A-01` 为关系查询、状态更新、固定和证据读取补运行时参数校验、边界限制和统一错误。
2. `A-02` 单条 AI 解释增加隐私同意、超时、结构化 JSON 白名单、失败原因与测试；严格限制为该关系、双方各最多两段/每段 500 字符、450 输出 tokens。
3. `A-03` AI 不得创建关系、改变状态或覆盖人工方向；失败只影响解释结果。
4. `A-04` 将问答收敛为侧栏一级 `问答（实验）`，引用可跳转 Explorer；不参与关系发现。

**验收**：非法 IPC 参数被拒绝；AI 未配置、拒绝外发、超时和非法 JSON 时本地关系卡仍可操作；任何 AI 请求都不触发全量候选。

### 阶段 E：质量、性能与发布（P0 发布门禁）

**负责人：QA & Release；所有角色修复自己模块的失败。**

1. `Q-01` 关系单元回归：引用、实体、通用词、无证据、隐藏/固定、重索引、删除、失联、导出恢复和旧备份迁移。
2. `Q-02` Playwright Electron E2E：PRD 第 8 节完整流程，包括证据、跳转、固定、画板、隐藏、重启/恢复和 AI 失败。
3. `Q-03` 画板 E2E：16 种端口组合、去重/自环限制、属性与布局持久化。
4. `Q-04` 20/50/200 份固定语料性能基准，记录导入、单文件增量重索引和 Explorer 查询 P50/P95；20-50 份材料的查询 P95 必须小于 1 秒。
5. `Q-05` 真实 Windows 干净环境验证：NSIS、portable、无密码工作区、SQLite、中文/长路径、导入导出和文件监听。

**验收**：TypeScript、单元测试、构建、E2E、性能门槛和 Windows 验收全部通过；记录版本、包 hash、步骤、截图和已知问题。

## 5. 串并行关系

```text
G-01 -> G-02 -> G-03/G-04 -> G-05
                         |-> E-01/E-02 -> E-03/E-04 -> E-05 -> C-01/C-02/C-03/C-04
                         |-> A-01 -> A-02/A-03 -> A-04
所有阶段 -----------------------------------------------> Q-01 -> Q-02/Q-03/Q-04 -> Q-05
```

- 阶段 A 是所有产品闭环的前置条件。
- 阶段 B 的 `E-03` 是主题画板验收的硬依赖。
- 阶段 D 可与阶段 B/C 并行，但不能阻塞无 AI 的本地闭环。
- 阶段 E 不接受“手工验证替代自动化”或“性能未测先发布”。

## 6. 审批决策

请确认以下建议后再进入实现：

| 决策 | 建议 | 原因 |
| --- | --- | --- |
| 固定关系的归属 | 固定时必须选择已有主题，或在同一弹层创建主题 | 避免“已经固定但画板找不到” |
| PDF 证据定位 | 0.1 使用页码/摘录降级，不承诺 DOM 级高亮 | PDF 解析文本与视觉页布局不稳定 |
| 端口视觉 | 每边展示一个双向端口，内部映射 source/target handle | 保留四边任意连接，降低重叠端口操作难度 |
| 问答入口 | 侧栏一级 `问答（实验）` | 与 PRD 的一级实验能力一致，且避免混入工作台主任务 |
| 加密工作区 | 保留已有兼容能力，但不作为 0.1 发布阻断项；新建默认无密码 | 符合“本地运行且无需密码创建”的已确认要求 |

## 7. 审批后动作

批准后按阶段 A 开始，由 `Integration Owner` 建立任务看板，采用上述 ID 创建/更新 GitHub Issue，并在每个阶段完成时提交一次可运行的集成验收。任何超出 PRD 第 7 节非目标的需求，进入 0.2 backlog，不插入 0.1 发布线。
